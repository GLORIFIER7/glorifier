## GitHub Bounty Monetization Pipeline

GLORIFIER treats GitHub bounty work as a governed economic workflow:

**DISCOVER → VERIFY FUNDING → VERIFY ELIGIBILITY → CLAIM → SOLVE → PR/REPORT → ACCEPTANCE → VERIFY PAYOUT → SETTLE**

### Economic truth

- Advertised bounty ≠ verified funding.
- Funding promise ≠ revenue.
- Accepted PR/report ≠ payment.
- Wallet balance ≠ revenue.
- Only canonical payment evidence after acceptance can become **VERIFIED_REVENUE**.
- Mirror issues are discovery signals only; canonical platform/chain evidence is required.

### Security boundary

Security bounty work is only performed against explicitly authorized, in-scope targets and under the program's rules. GLORIFIER does not perform unauthorized testing, social engineering, destructive testing, or excessive automated scanning.

### Permanent discovery

The scheduled workflow scans public GitHub bounty signals every six hours. Discovery is evidence-producing only; it does not automatically claim work, submit external PRs, accept terms, or record revenue.

### Current live example

GitHub's official Bug Bounty program is legitimate and publishes reward guidelines, but those amounts are guidelines rather than guaranteed payouts. GLORIFIER therefore records none of those amounts as revenue until an actual award/payment is confirmed.
